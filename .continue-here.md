Russian *datacenter* says little about the same key through TSPU on residential.

That input is now suspect. The cheapest large win available is **filtering
verified-russia.txt to Shadowsocks only** — on this evidence it moves 29% toward
~100%, because non-SS keys are pure dead weight in their client. Small change to
tier ordering, no new machinery. NOT YET DONE — it was the next step when paused.

### ALIVE-03 (4aab1de2)
`HTTPOpts` exposed no timeout field, so xray-knife defaulted its HTTP client
timeout to `--mdelay`. With `-d 5000` and a 10 MB body that capped every
measurement at EXACTLY 16 Mbps, and the read error is discarded upstream
(`b, _ := io.ReadAll`) so a partial download reported success. 54.2% of published
values sat at/below that ceiling; the 14.0 Mbps bin alone was 20.24% — the single
largest bin, a property of the clock not of proxies. Since `--min-speed 12`
filters on it, 6 countries with live keys published nothing.
Stage 2 now passes `TimeoutMs: 20000`. Also extracted `httpArgs()` because
`HTTPTest` had NO test asserting which flags reach the engine.

### ALIVE-05 (27bdd4d6)
`probeOne` returned a bare bool, so "binary missing / engine crashed / ctx
cancelled" was indistinguishable from "key is dead" — and the error path was
commented *"definitively dead"* directly beneath a doc comment explaining that
xray-knife exits 0 for both pass and fail. `DropRate` divided by total jobs with
no error term, so an unusable prober scored 1.0 and tripped the 75% abort,
republishing stale output. Now tri-state; errored keys are KEPT. The existing
test asserted `DropRate == 1.0` for a nonexistent binary — it pinned the bug as
correct behaviour, so it was inverted.

### ALIVE-04 (28989fd5)
Three bugs in one line of the igareck fetch: `head -10 > file` sat INSIDE the
two-file loop so the second iteration truncated the first; the grep required the
literal `security=reality` so differently-spelled files contributed zero; and
`head -10` capped before dedup. Pool landed at 6-11 against an intended 20+ and
the working bridge was nearly always the same host. 33 runs (8.5% of successes)
published nothing while reporting GREEN.
