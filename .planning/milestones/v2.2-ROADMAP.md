# Milestone v2.2 — ru-verified-10 (ARCHIVED 2026-08-20)

**Goal:** Ship `subs/verified-russia.txt` with ~10 keys verified from a Russian
vantage point, proving the architecture at small scale before scaling up.

**Status at close:** Shipped, but the goal was met in letter and missed in
spirit. The file exists and is verified through an RU bridge every 30 min. What
v2.2 did NOT establish is that those keys work on the operator's actual
residential line — the acceptance criterion was always CI-side.

## Phases

- ✅ **22.1** RU verification investigation — proved 95% pass from Frankfurt vs
  0% from residential RU. Root cause: same key, different vantage point.
- ✅ **22.2** saleapp source integration — 9 RU-curated aggregators added.
- ✅ **22.3** verify-russia.yml bridge architecture — xray-knife proxy inbound →
  SOCKS5 → proxychains4, 2-stage filter, never-empty-overwrite guard.
- ✅ **22.4** Per-key reliability tracking + protocol-tier measurement.
- ⚠️ **22.5** Document & ship — partially done; superseded by v2.3.

## What actually shipped

1. **RU-bridge verification** (`verify-russia.yml`): 30-min cadence, publishes
   `subs/verified-russia.txt`. The only RU-side signal in the project.
2. **First real protocol measurement** (run 31562489245, full pool 565/565):
   ss 60.3% pass / 582ms median · vless 50.6% / 769ms · trojan 0/36 (stale keys).
   **Shadowsocks — excluded as "TSPU blocks AEAD" — led on both.** That
   exclusion had never been measured: tier E sat at index ~502 of 565 while the
   sweep exited at 150 passes, so its record was 0/0, not 0/63.
3. **Failure recording.** Every one of the prior 19,132 history records was
   `alive:true` — a survivors log from which no pass rate was derivable. Now
   both outcomes are recorded, which is what made #2 possible at all.
4. **Endpoint-aware selection.** "Top 3 per country" was frequently one host
   under three UUIDs (`subs/vless/DE.txt` shipped `104.18.32.47:2096` ×3), so a
   single outage killed every key for that country.
5. **xray-knife pinned to v10.1.1.** v9's bundled xray-core SIGSEGVs on trojan
   splithttp configs, silently freezing `subs/trojan/` for 26 days while the job
   reported success. Pinned at all five install sites with a drift test.
6. **all-results.csv** became a true union of four protocols (it had copied the
   first artifact then `break`ed) and gained a row cap after hitting GitHub's
   100 MB blob limit and rejecting six consecutive pushes.

## Why v2.2 closes without reaching "99% alive"

The milestone measured aliveness from GitHub Actions runners and an RU-datacenter
bridge. Neither is the operator's residential path through TSPU. v2.2's own notes
record the gap (95% Frankfurt vs 0% residential) but its acceptance criteria never
crossed it. v2.3 makes the operator's own client the measurement instrument.
